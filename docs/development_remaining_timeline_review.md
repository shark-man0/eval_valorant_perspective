# Remaining timeline review and connection gaps

This follow-up preserves the frozen recognizers and shared state engine. It
completes a bounded inspection backlog; it does not establish population accuracy
or qualify a new default.

## Sealed ACTIVE revisions

The existing optional ACTIVE-clock experiment revised 121 previously UNKNOWN
native points across seven exposed DEVELOPMENT matches. Fourteen first/last
centers had already been inspected. Before accessing more pixels, all remaining
107 exact targets were frozen as the set difference by Source hash, PTS,
timebase, decoded pixel hash and dimensions. Original media were admitted and
their hashes verified before/after bounded decoding. All 107 target pixels
reproduce exactly; fresh acquisition epochs are retained. No label, initial state,
roster or Source-conditioned recognition rule was supplied.

AI visual inspection of all 107 targets supports ACTIVE at each point: current
combat/movement, planting, running-round battle reports and contemporaneous HUD
context are visible. No contradicted or undecidable target was recorded.
Together with the preceding 14, the selected backlog is now 121 AI-supported
display points. This is AI inspection, not human GT or a 100% recognition-accuracy
claim. The set contains only previously UNKNOWN-to-ACTIVE revisions; it cannot
measure false negatives, false boundary events, all wrong known states or whole
intervals. No inspection result is fed into inference or training.

## Armor and Weapon

The common Profile used by these experiments declares only HP in its
`player_hp_armor` reader. Neither `ammo_current_weapon` nor `weapon_inventory`
has a configured reader. Existing numeric-field and weapon-template readers,
the value-only adapter and the JSON/CSV/viewer path already support these values;
the missing part is a validated common Profile/asset configuration.

In the preserved 24-native-frame HUD cohort, HP produces six candidates and
18 geometry abstentions. Armor has 24 unconfigured results. Weapon has two
unconfigured reader slots per frame (48 slots across the same 24 frames), not
48 independent samples. No Armor/Weapon accuracy is available. A weapon registry
contract is not a populated recognition bank, and OCR of a multi-weapon inventory
does not by itself identify the selected weapon. The existing Profile is not
silently expanded or used to infer recorder life.
