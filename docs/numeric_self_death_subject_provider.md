## Missing connection and implementation

The existing image session could consume separately supplied Subject proof, but
its positive test provider assembled Subject observations in test code. It had
no implementation joining current image measurements to the actual qualified
native source/scene entrance. `experimental/numeric_subject_provider.py` now
implements `QualifiedNumericImageProvider` for that specific entrance.

It takes the current `SelfDeathImageRecognizer`, an externally reviewed numeric
qualification, actual `NativeSourceFrame` objects, and the existing
`NativeLifecycleAnalysis` produced for those frames. It is passed as the existing
session `frame_provider`; no second image reader, new default application caller
or saved diagnostic JSON entrance is introduced. The session owns recognition
of current pixels before invoking the provider. Its original unqualified image
reading remains unchanged.

Construction requires exact source, code, profile, dependencies, cadence and
current release bindings. The numeric certificate's `native_temporal_continuity`
review must reference the exact separate native qualification report. The
default scene entrance requires scene continuity with the current shared
recognizer fingerprint. The explicit source-assured alternative is described
below; failure of a scene proof never selects it automatically.
Changing the provider file invalidates release qualification. Missing or stale
qualification cannot install the producer; no real certificate is generated by
this implementation.

The provider has a bounded source window supplied by the existing native
entrance. Scene rows are deep-copied and their proofs serialized immutably;
later mutation cannot replace a missing proof. Caller responsibility remains to
use producer-owned native results, preserve their artifacts and finish the
existing decoder's terminal source verification before publishing run results.

## Per-frame proof

For every image reading, the provider checks the next actual native frame's
source SHA, exact ticks/timebase, source epoch and pixel hash. It calls the
existing native encoded/pixel verifier. Missing/reordered input, changed encoded
bytes/pixels, foreign source or producer, explicit content jump/discontinuity
and changed qualification/code reject and poison this provider session.

After the source head, every adjacent pair requires the existing qualified
`global_scene_continuity` proof. The unchanged `_scene_attested()` predicate
requires multiple distinct background cells spanning both rows and columns,
accepted NCC, clock independence and checked background. The provider also
checks original current/previous PTS and pixels, exact source/epoch/timebase,
qualification/profile/code bindings and stable scene segment. A Boolean
permission or newly computed arbitrary hash cannot replace those measurements.

The source head has no predecessor and cannot bridge any earlier context.
The existing recognizer independently requires actual onset predecessors and
native corroboration. A rejected window is not silently rearmed: a new genuine
source session is needed. This producer does not infer Round numbers or a new
Round from elapsed time, a raw reset or GT.

New Subject observations are constructed only under the reviewed producer's
exact qualification:

- Recording-player binding needs the actual current victim marker's three
  numeric structural supports and yellow support, all >=0.90.
- Victim role needs its independent current weapon-template NCC >=0.90 and
  current plate support where that profile measures it. Geometric/ability-only
  roles never gain a synthetic weapon score or satisfy this numeric contract.
- Death transition uses the actual self-referential caption's original fresh
  onset and predecessor, retained by the same session-owned recognizer.
- Current self-caption or separately accepted Report header can corroborate
  Report presence. A generic header cannot open a transition or identify Self.

`review_sha256` references each independently reviewed producer component, not
a claim of manual labeling of every runtime image. No stored CANDIDATE/UNKNOWN
observation is rewritten. These event-subject observations grant no HUD identity,
owner, HP, Armor, Weapon, Ammo, Alive or location. Source scene proof contributes
continuity only, never Self. The constructor does not require a timer, score,
purchase-phase value or live-HUD confidence at the current frame.

Each accepted source pair's confidence cannot exceed its original cell scores.
New Subject proof support is conservatively capped by that pair's accepted
support as well as its own actual measurement. Original image scores remain
unchanged. The unchanged consumer applies all original role, temporal, duplicate
and ownership checks before Event construction.

references. It returns fresh data for private artifact storage; it is not a
qualification loader or resume mechanism. Existing Event, RoundPackage, Trace,
SQLite and review-state Schemas remain unchanged. A provider with a source break
cannot be reused through a generic reset. Complete application resume and

## Explicit existing source-assured entrance

The initial provider accepted only the scene entrance. Inspection of the
archived Full and the current native qualification artifacts showed that both
use the existing SHA-bound input-assurance route, without a `scene_continuity`
component. Requiring a new scene certificate solely to use those source rows
was an unnecessary connection blocker. It was not evidence that Self/Death
had already qualified.

`source_mode='source_assured'` now explicitly selects that existing route. It
requires the original `UneditedInputContract` and its file, exact numeric
certificate source, unchanged input-contract digest, and the current native
qualification's `timer`, `purchase_phase` and `ui_transition` components. Each
original producer row passes the existing `validate_assured_row()` contract.
No source policy, global qualification loader, threshold or public schema was
changed. The default remains `source_mode='scene'`.

Both routes retain exact source/PTS/timebase/epoch/pixel binding, actual PNG
verification, strict native adjacency, repeated-pixel rejection and explicit
source-break rejection. A removed or changed assurance file poisons the
source-assured session. An assurance never transfers to a foreign video.
An invalid session requires a new source entrance; it cannot bridge the break.

The retained proof body records the input-contract and native-qualification
digests, native profile/code, both source bindings and original producer
evidence. `continuity_provenance()` exports these bodies under
`source_assured_proofs`, keyed by the actual serialized proof hash. These are
source-assurance proofs, not fabricated background NCC proofs. Assurance has
no numeric confidence, does not boost measured role confidence, supplies no
Self identity, and does not turn an absent timer/phase observation into a
qualified value. The separate numeric Subject/role/transition certificate is
still mandatory before this provider can be installed.
