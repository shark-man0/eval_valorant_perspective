# 継続学習基盤（Issue #105・#97）

録画を追加するたびに、データ取り込み、特徴抽出、学習、検証、採否判定までを同じ手順で回す基盤。人手の正解ラベルに頼らず、外部知識（#96）、自己教師あり学習、別センサーによる弱ラベルを組み合わせる。

学習したモデルは開発用の登録簿の中でだけ有効になる。正式パイプラインの認識器には自動接続しない（接続には別途承認が要る）。

## 流れ

```
録画 → HUD切り出し（scripts/knowledge/extract_hud_crops.py、非公開）
     → データ登録簿（元動画のSHA-256と物理試合IDで一度だけ割当）
     → 特徴キャッシュ（アーカイブのSHA-256 × 抽出器の版。新規分だけ計算）
     → 学習（外部知識のアンカー ＋ 自己教師あり射影 ＋ 弱ラベル）
     → 採否ゲート（VALIDATIONだけで判定、非回帰）→ ACTIVE / REJECTED、履歴、ロールバック
     → 報告（DEV_COMPARISON：開発比較用の固定セット）
     → 独立評価（INDEPENDENT_TEST：未露出動画だけ。明示コマンドでのみ実行）
```

```sh
# 録画（切り出しアーカイブ）を追加して1サイクル回す。元動画のハッシュ一覧が必須
PYTHONPATH=src python -m valorant_ai_coach.learning cycle --workspace PRIVATE_DIR --cache ASSETS \
  --manifest VIDEO_HASHES.json CROPS/*.zip
# 未露出の録画だけで、現在のACTIVEモデルを独立評価する
PYTHONPATH=src python -m valorant_ai_coach.learning independent --workspace PRIVATE_DIR --cache ASSETS
# 学習データ量と精度の関係を測る
PYTHONPATH=src python -m valorant_ai_coach.learning curve --workspace PRIVATE_DIR --cache ASSETS --sizes 1,2,4,8,16
# 状態確認・一つ前のモデルへ戻す
PYTHONPATH=src python -m valorant_ai_coach.learning status --workspace PRIVATE_DIR
PYTHONPATH=src python -m valorant_ai_coach.learning rollback --workspace PRIVATE_DIR
```

ワークスペース（登録簿、特徴、モデル、レポート）はすべて非公開ディレクトリに置く。

## 構成要素

| モジュール | 役割 |
|---|---|
| `learning/registry.py` | 追記専用の登録簿。元動画のSHA-256と物理試合IDを必須にし、どちらも複数の分割にまたがらない。同じ元動画を別IDで再登録すると `LeakageError`。分割は TRAIN / VALIDATION / DEV_COMPARISON / INDEPENDENT_TEST。INDEPENDENT_TEST には、登録時に未露出と申告した新しい物理試合だけが入る |
| `learning/features.py` | 内容アドレス型の特徴キャッシュ。録画を足しても既存分は再計算しない |
| `learning/models.py` | NumPyだけで動く学習器（主成分射影、プロトタイプ分類器と棄権マージン、信頼度付き自己学習） |
| `learning/model_registry.py` | モデルの版管理。データ指紋・設定・指標を保存し、非回帰ゲートで採否を決める。履歴は `history.jsonl`、`rollback` で一つ前に戻せる |
| `learning/portrait_identity.py` | 最初の学習課題（下記） |
| `learning/pipeline.py`, `__main__.py` | 1サイクルの実行、学習曲線、CLI |

採否ゲート（`GatePolicy`）はVALIDATIONの指標だけを読む。弱参照との整合率が0.005以上改善し、味方チーム再現率が下がらず、棄権率が5ポイント以上増えないときだけ採用する。VALIDATION以外の指標をゲートに指定すると `ValueError` になる。DEV_COMPARISONは報告専用で、採否には使わない。

## 最初の課題：上部マッチバーのポートレートのエージェント特定

上部バーのポートレート（縮小された顔画像）から、各プレイヤーのエージェントを特定する。味方・敵の構成が分かれば、ロールや武器の文脈、キルフィードの照合に使える。

使う信号は3つで、いずれも人手の正解ラベルを使わない。

1. **外部知識**：公式のエージェント画像を顔の位置で切り出し、エージェントごとの基準点にする（ゼロショット）。
2. **自己教師あり**：TRAIN試合の未ラベルのポートレートで主成分射影を学習し、HUDの描画に合った特徴空間にする。
3. **別センサーの弱ラベル**：TRAIN試合では、アビリティHUD（#96の公式アイコン照合）から「録画者のチームにいたエージェント」が分かる。各フレームの味方ポートレートをその集合へ一対一で割り当て、敵側は試合中に固定の5人へ割り当てる。

### 評価指標

弱参照との整合率と、実際の認識精度を分けて報告する。

- `weak_ref_consistency`（旧 `ally_set_consistency`）：味方ポートレートの予測のうち、その試合のアビリティHUDが示す味方集合に入っている割合。集合との整合を見るだけで、1枚ごとの正誤ではない。
- `ally_team_recall`：予測で多かった上位のエージェントと、味方集合の重なり
- `exact_ref_accuracy`：**1枚ごとの認識精度**。上部バーに味方のポートレートが1枚だけあり、同じ瞬間のアビリティHUDが生存中の選手を高スコア（0.8以上）で示している場合、その1枚の正解はHUDのエージェントに確定する。評価する試合のHUDは学習に使っていないので、独立した正解として使える。
- `reviewed_accuracy`：人が確認したラベルを `--reviewed-labels` で渡したときの精度（今回は未使用）。上部バーの顔は公式画像と絵柄が異なり、目視でも確信できない枚が多かったため、目視ラベルは正解に採用しなかった。

### 実動画での結果（36試合）

36試合は、元動画のハッシュつきの登録簿によって TRAIN 21・VALIDATION 6・DEV_COMPARISON 9 に割り当てられた。前回報告の固定9試合はそのまま DEV_COMPARISON として残し、開発比較にだけ使う（INDEPENDENT_TEST は0試合で、今後の未露出動画で作る）。

| 方式 | 学習試合数 | 弱参照との整合率 | 味方チーム再現率 | 1枚ごとの認識精度（172枚） |
|---|---|---|---|---|
| 外部知識のみ（ゼロショット） | 0 | 0.578 | 0.722 | 0.692 |
| ＋自己教師あり＋弱ラベル | 1 | 0.622 🟢 | 0.611 🔴 | 0.663 🔴 |
| 同上 | 2 | 0.724 🟢 | 0.711 | 0.709 🟢 |
| 同上 | 4 | 0.739 🟢 | 0.717 | 0.692 |
| 同上 | 8 | 0.735 | 0.789 🟢 | 0.727 🟢 |
| 同上 | 16 | 0.786 🟢 | 0.833 🟢 | 0.843 🟢 |
| 同上（採用） | 21 | **0.813** 🟢 | **0.856** 🟢 | **0.924** 🟢 |
| ＋弱ラベル（自己教師ありなし） | 21 | 0.801 | 0.856 | 0.907 |
| ＋自己教師ありのみ（弱ラベルなし） | 21 | 0.583 | 0.722 | 0.663 |

- 録画が増えるほど精度が上がった。1枚ごとの認識精度は、ゼロショットの0.692から21試合で0.924（+0.232）になった。
- 効いているのは別センサーの弱ラベルで、自己教師あり射影だけでは上がらない。射影は弱ラベルと組み合わせたときに +0.017 上乗せする。
- 1試合だけの学習では精度が下がる。少数試合の弱ラベルに引っ張られるためで、2試合目からは基準を上回る。
- 採否判定に使うVALIDATION 6試合（評価可能5試合）では、弱参照との整合率0.851、味方チーム再現率0.840だった。
- 主成分射影に白色化を入れた最初の版は、5試合時点の試験で 0.471 から 0.290 🔴 に下がった。白色化を外して既定にした。

### 増分処理と採否ゲート

- 36試合の初回サイクル（特徴抽出を含む）は508秒、特徴がキャッシュ済みの状態での学習曲線の全計算（14構成）は119秒だった。
- 元動画のハッシュつきで作り直した登録簿は、以前の分割と完全に一致した（同じ物理試合IDとシードによる決定的な割当）。指標も同一だった。
- 採否ゲートは、単体テストで「DEV_COMPARISONだけが改善した版」「味方チーム再現率が下がった版」を不採用にすることを確認している。

## 制約と今後

- 弱ラベルは、録画者のチームの集合が4人以上観測できた試合だけで作る。観戦が少ない試合は弱ラベルを出さない。
- ポートレートは5秒間隔・半分の解像度で切り出しているため、顔は約21ピクセルしかない。全解像度で切り出せば精度の上限は上がる見込み。
- 同じ基盤に、アビリティHUDの読み取り（すでに高精度）やキルフィードの照合など、別の課題を追加できる。課題は `extract / train / evaluate` の3関数をそろえれば登録できる。
