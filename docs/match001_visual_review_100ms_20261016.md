## ソースの性質：ユーザー確認済み

**2026-10-16のユーザーによる正確な説明**：`match_001` は **Outplayedで元の長い録画から切り出したクリップ**であり、**切り出した区間の内部は一切編集していない**。今後の本番利用・検証でも動画内容の編集は行わない方針である。

- クリップの**境界における切り出し**と、クリップ**内部の削除・連結・並べ替え・速度変更**は分けて扱う。後者はないとのユーザー保証を採用する。
- 約171秒の動画は「マッチ全体が記録されている」という意味ではない。冒頭でスコアが既に0–1、末尾はラウンド中のEOFである。映像外のラウンド開始・終了は推定しない。
- 約81.9秒のフレーム重複と急激な画面変化は**観測事実**として残すが、「編集された証拠」ではない。ゲーム内の画面遷移、録画側のフレーム出力、その他の事情はこの観測だけでは識別できない。
- **未編集保証は時間軸や認識精度の万能証明ではない**。native PTS/epoch/フレーム整合性検査、実際の画面変化・不連続をまたぐ証拠の無断結合禁止、誤認識への保護は維持する。
- `datasets/input_contracts/match_001.unedited.json` はこの動画SHAへの明示的保証。今後の別動画についてもユーザー方針は未編集だが、契約・SHA・由来を各ソースに記録するまでは同じファイルの保証を流用しない。

この記録は従来の「Outplayed-cut」という履歴と矛盾しない。ただし「切り出したから内部も編集済み」という解釈、あるいは「未編集だからマッチ全体が揃っている」という解釈はいずれも誤り。

## ±0.1秒の設計提案（未採用）

1. **検出**：元PTSを完全精度で保存し、GT時刻に依存せず購入フェーズ・時計・スコア・終了画面の実観測でイベントを確定する。
2. **評価**：独立GTの単一点なら `abs(predicted - truth) <= 0.1` を提案。GTが既に許容区間を持つときは、±0.1秒の二重加算を避けて契約を明文化する。
3. **表示**：ユーザー向けには0.1秒単位で十分。比較判定の前に丸めたり、正解時刻へスナップしたりしない。
4. **効率**：低密度で候補UIを検索し、候補前後だけ密に確認する案をベンチマークする。10fps一律への変更、時系列証拠の省略、サンプル間の未観測イベントの補完は行わない。
5. **負例**：147.7秒の死亡を`round_end`にしない。前ラウンドの残存戦闘レポートやクリップEOFでイベントを発行しない。81.9秒の急変は編集の証拠と混同しない一方、実際のソース整合性異常を無視して証拠をつなげない。
