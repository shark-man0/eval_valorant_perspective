# 継続学習基盤（Issue #105・#97）

録画を追加するたびに、データ取り込み、特徴抽出、学習、検証、採否判定までを同じ手順で回す基盤。人手の正解ラベルに頼らず、外部知識（#96）、自己教師あり学習、別センサーによる弱ラベルを組み合わせる。

学習したモデルは開発用の登録簿の中でだけ有効になる。正式パイプラインの認識器には自動接続しない（接続には別途承認が要る）。

## 流れ

```
録画 → HUD切り出し（scripts/knowledge/extract_hud_crops.py、非公開）
     → データ登録簿（物理試合単位で TRAIN / VALIDATION / FROZEN_TEST に一度だけ割当）
     → 特徴キャッシュ（アーカイブのSHA-256 × 抽出器の版。新規分だけ計算）
     → 学習（外部知識のアンカー ＋ 自己教師あり射影 ＋ 弱ラベル）
     → 検証（VALIDATION と固定のFROZEN_TEST）
     → 採否ゲート（非回帰）→ ACTIVE / REJECTED、履歴、ロールバック
```

```sh
# 録画（切り出しアーカイブ）を追加して1サイクル回す
PYTHONPATH=src python -m valorant_ai_coach.learning cycle --workspace PRIVATE_DIR --cache ASSETS CROPS/*.zip
# 学習データ量と精度の関係を測る
PYTHONPATH=src python -m valorant_ai_coach.learning curve --workspace PRIVATE_DIR --cache ASSETS --sizes 1,2,4,8,16
# 状態確認・一つ前のモデルへ戻す
PYTHONPATH=src python -m valorant_ai_coach.learning status --workspace PRIVATE_DIR
PYTHONPATH=src python -m valorant_ai_coach.learning rollback --workspace PRIVATE_DIR
```

ワークスペース（登録簿、特徴、モデル、レポート）はすべて非公開ディレクトリに置く。

## 構成要素

| モジュール | 役割 |
|---|---|
| `learning/registry.py` | 追記専用の登録簿。物理試合ごとにハッシュで分割先を決め、一度決めた分割は変えない。同じ試合の別ファイルは同じ分割に入り、別の分割を指定すると `LeakageError` |
| `learning/features.py` | 内容アドレス型の特徴キャッシュ。録画を足しても既存分は再計算しない |
| `learning/models.py` | NumPyだけで動く学習器（主成分射影、プロトタイプ分類器と棄権マージン、信頼度付き自己学習） |
| `learning/model_registry.py` | モデルの版管理。データ指紋・設定・指標を保存し、非回帰ゲートで採否を決める。履歴は `history.jsonl`、`rollback` で一つ前に戻せる |
| `learning/portrait_identity.py` | 最初の学習課題（下記） |
| `learning/pipeline.py`, `__main__.py` | 1サイクルの実行、学習曲線、CLI |

採否ゲート（`GatePolicy`）は、FROZEN_TESTの主指標が0.005以上改善し、VALIDATIONの指標が下がらず、棄権率が5ポイント以上増えないときだけ採用する。

## 最初の課題：上部マッチバーのポートレートのエージェント特定

上部バーのポートレート（縮小された顔画像）から、各プレイヤーのエージェントを特定する。味方・敵の構成が分かれば、ロールや武器の文脈、キルフィードの照合に使える。

使う信号は3つで、いずれも人手の正解ラベルを使わない。

1. **外部知識**：公式のエージェント画像を顔の位置で切り出し、エージェントごとの基準点にする（ゼロショット）。
2. **自己教師あり**：TRAIN試合の未ラベルのポートレートで主成分射影を学習し、HUDの描画に合った特徴空間にする。
3. **別センサーの弱ラベル**：TRAIN試合では、アビリティHUD（#96の公式アイコン照合）から「録画者のチームにいたエージェント」が分かる。各フレームの味方ポートレートをその集合へ一対一で割り当て、敵側は試合中に固定の5人へ割り当てる。

### 評価指標

FROZEN_TEST試合のアビリティHUDが示す味方集合を参照に使う。参照は人手の正解ではなく、学習に使っていない独立のセンサーである。

- `ally_set_consistency`：味方ポートレートの予測のうち、その試合の味方集合に入っている割合
- `ally_team_recall`：予測で多かった上位のエージェントと、味方集合の重なり

### 実動画での結果（36試合）

36試合は、登録簿によって TRAIN 21・VALIDATION 6・FROZEN_TEST 9 に割り当てられた（物理試合単位、ハッシュで決定）。評価はすべて固定のFROZEN_TEST 9試合で行った。

| 方式 | 学習試合数 | 弱ラベル数 | ally_set_consistency | ally_team_recall |
|---|---|---|---|---|
| 外部知識のみ（ゼロショット） | 0 | 0 | 0.578 | 0.722 |
| ＋自己教師あり＋弱ラベル | 1 | 1,973 | 0.622 🟢 | 0.611 🔴 |
| 同上 | 2 | 5,630 | 0.724 🟢 | 0.711 |
| 同上 | 4 | 13,020 | 0.739 🟢 | 0.717 |
| 同上 | 8 | 24,271 | 0.735 | 0.789 🟢 |
| 同上 | 16 | 49,489 | 0.786 🟢 | 0.833 🟢 |
| 同上（採用） | 21 | 62,962 | **0.813** 🟢 | **0.856** 🟢 |
| ＋弱ラベル（自己教師ありなし） | 21 | 62,962 | 0.801 | 0.856 |
| ＋自己教師ありのみ（弱ラベルなし） | 21 | 0 | 0.583 | 0.722 |

- 録画が増えるほど精度が上がった。ゼロショットの0.578から、21試合で0.813（+0.235）になった。
- 効いているのは別センサーの弱ラベルで、自己教師あり射影だけでは0.58前後のまま変わらない。射影は弱ラベルと組み合わせたときに +0.012 上乗せする程度だった。
- 1試合だけの学習では、味方チームの再現率が0.611に下がった。少数試合の弱ラベルに引っ張られるためで、2試合目からは基準を上回る。
- VALIDATION 6試合では0.851・0.840で、FROZEN_TESTと大きくは離れていない。
- 主成分射影に白色化を入れた最初の版は、5試合時点の試験で 0.471 から 0.290 🔴 に下がった。公式画像の基準点がHUDの分布から外れた方向を強調したためで、白色化を外して既定にした。

### 増分処理と採否ゲート

- 36試合の初回サイクル（特徴抽出を含む）は508秒、特徴がキャッシュ済みの状態での学習曲線の全計算（14構成）は119秒だった。
- 採否ゲートは実データで確認した。5試合時点では白色化版（0.290）を最初のACTIVEにし、白色化なしの版（0.654）が改善として置き換えた。36試合のワークスペースでは、21試合で学習した版（0.813）を最初のACTIVEとして登録した。

## 制約と今後

- 弱ラベルは、録画者のチームの集合が4人以上観測できた試合だけで作る。観戦が少ない試合は弱ラベルを出さない。
- ポートレートは5秒間隔・半分の解像度で切り出しているため、顔は約21ピクセルしかない。全解像度で切り出せば精度の上限は上がる見込み。
- 同じ基盤に、アビリティHUDの読み取り（すでに高精度）やキルフィードの照合など、別の課題を追加できる。課題は `extract / train / evaluate` の3関数をそろえれば登録できる。
