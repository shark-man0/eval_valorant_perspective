# Development multi-marker positions

`DevelopmentMarkerProposals` preserves existing `MarkerReferenceInspector`
proposals from both positive and control references. The previous single-target
pool may reject a frame for competing icons, a negative match, or context. This
separate path preserves visible appearances without choosing a recorder target.
It does not modify the existing trackers, thresholds, eligibility or version gate.

Call `observe` with a native-bound sample, the exact decoded BGR frame, explicit
minimap ROI, an existing bounded appearance pool, calibration profile and the
separately measured context eligibility. The decoded pixel digest must match.
The caller must verify the encoded frame digest in its acquisition manifest.
References are content-fingerprinted and rechecked before returning. Invalid
libraries raise rather than return a partial bank. There are at most four
libraries with at most 32 proposals each; truncation and per-library duplicates
are explicit. Do not interpret proposal count as distinct marker count.

An explicitly selected non-Production map uses the existing outline calibrator
on every frame. Its registered floor mask rejects off-floor transformed points.
`geometry_only_map_position_norm` is raw, unverified geometry, including when a
context is blocked. It must not enter a recorder path or dwell-time calculation.
The ordinary `map_position_norm` remains null. Version compatibility is UNKNOWN,
there is no selected self position, and Fact/events/tracks/interpolation remain
empty. Context eligibility does not authenticate ownership or current map build.
The API has no previous-target state or cross-frame association.

## Known-development failure analysis

The same previously reviewed 20 images were reused for triage, not independent
evaluation. All 15 annotated recorder markers are inside the ROI. Existing
single-target outputs still select zero of them. Reasons on the 15 human
self-alive images are context blocks6, appearance unavailable5, ambiguity2 and
wrong target2. The new path retains existing raw proposals matching four of
15 recorder annotations; two also pass raw geometry/floor checks. These four
were already generated by the inspector. This is recovery of rejected proposals
into a multi-position representation, not improved template detection accuracy.
It also retains teammate and OTHER appearances. No member is selected as self.

The six blocked self-alive images do not establish six false rejections.
The human label includes purchase phase. Five carry a report-overlay cue and
one a purchase cue; more than one cue can be present. Their exact eligibility
and phase are not independently annotated. Report presence alone cannot prove
current death, and purchase alone cannot identify the current player. Separate
subject, liveness, phase, overlays and eligibility when collecting further GT.

Appearance vocabulary is still a major limitation. Some human recorder icons
have high nearby similarity but their proposal center misses the fixed 2px
annotation tolerance. Neither that tolerance nor similarity thresholds were
relaxed. An exploratory shape-only search saturated the bounded search with
background candidates and is not adopted. Existing reference roles must not be
transferred between recordings as semantic self/nonself labels.
